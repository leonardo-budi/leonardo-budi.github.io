## 2026-07-01: Reading-width decision reversed for image-adjacent lists

Earlier the same day, `.case-list` was given a blanket `max-width: 620px` to match `.case-body`'s reading measure (see the editorial consistency pass above), on the reasoning that a bullet list should never be wider than the paragraph next to it. After seeing the real, implemented assets in context, Leo reviewed the whole page against his memory of the previous version and preferred the original, wider editorial pacing, specifically for sections where a list sits directly beneath a full-width image (Landscape, Challenge, Final Design). His framing: a large image should read as an editorial breakpoint that widens the whole moment, not force the content immediately below it back into the narrow prose column.

**Decision, superseded from earlier today, not silently overwritten:** `.case-list` no longer carries a blanket max-width. Only Principle's list (the one `.case-list` on this page with no image nearby, a pure continuation of its paragraph) keeps `max-width: 620px`, added directly as an inline style rather than a shared class rule. Landscape's, Challenge's, and Final Design's lists are back to the full column width (1020px at desktop), matching their images.

**Why this isn't a contradiction, just a correction informed by more context**: the original fix was reasoned from source/CSS alone, before real assets existed, when every `.case-list` on the page looked the same (a plain text list with no visual anchor). Once real images were in place, it became clear that three of the four lists are functionally part of an image block, not a text block, and should share the image's width rather than the paragraph's. The one list that genuinely is a text-block continuation (Principle) was correctly identified and kept narrow.

**Carried forward.** Any list added to a future page (Toko Mama, myBCA, Account Hub, Aryaduta) that sits directly below a full-width image should default to the image's width, not `.case-body`'s. A list that's a standalone continuation of body copy, with no image nearby, should match `.case-body` via an inline `max-width:620px`, the same pattern established here. This is a page-specific instance decision (an inline style per list), not a shared class rule, since the two cases need different widths and there's no single class that correctly describes both.
